### 核心策略：用“离线缓存”+“Oracle（上帝视角）”剥离工程难度，纯测理论上限

为了证明“Pandora's Box 规律在 RAG 中真实存在且有效”，你**绝对不要**一开始就去训练 Neural Probe 或搞 PPO。你要做的是**离线模拟（Offline Simulation）**。

#### 预实验步骤 1：构建完整的离线 RAG 轨迹缓存 (1-2天)
1. **选定一个小数据集**：从 HotpotQA 或 MuSiQue 中抽样 500-1000 个问题（作为训练/统计集），再抽 500 个作为测试集。
2. **无脑跑满 K 轮**：设定一个最大检索步数 $K=5$。对每一个 query，不管三七二十一，**强制它检索 5 轮，并生成 5 个答案**。
3. **记录所有数据**：
   * 记录每一步 $k$ 的中间状态。
   * 计算每一步生成的答案的真实 F1 分数 $Q(s_k)$。
   * 计算出**每一步的真实信息增益（Marginal Gain）**：$G_k = Q(s_k) - Q(s_{k-1})$。

#### 预实验步骤 2：验证 Pandora's Box 的 Oracle 效果 (1天)
这一步是为了回答 yzl：**“这套理论在 RAG 里到底好不好使？”**
1. **计算上帝视角的保留值（Oracle Reservation Value）**：
   利用你在那 1000 个训练集上统计出的 $G_k$ 的经验分布，硬算出每一步真实的 Weitzman 保留值 $r_k^*$（利用立项书中提到的积分公式，设一个虚拟的检索成本 $c$，比如 $c=0.05$）。
2. **在测试集上模拟停止**：
   在测试集上，对于每个 query，写一个简单的 `if` 逻辑：如果当前第 $k$ 步的真实 F1 分数 $Q(s_k) \geq r_{k+1}^*$，立刻停止，取当前的 F1 作为最终得分；否则继续。
3. **查看核心指标（Pareto 前沿）**：
   画一张图或拉一个表格，对比：
   * **Always K=1**：平均步数 1，F1 分数 X（极低成本，低质量）。
   * **Always K=5 (Upper bound)**：平均步数 5，F1 分数 Y（最高成本，高质量）。
   * **Oracle Pandora-RAG**：平均步数也许是 2.3，但 F1 分数达到了 Y 的 95% 以上！
   **👉 结论：只要能准确预估保留值，Pandora's Box 的停止策略确实能用一半的成本达到近乎满血的性能。这证明了理论在 RAG 中不是玄学！**

#### 预实验步骤 3：验证“无需重度微调也能 Work”（打消 RL 顾虑） (1-2天)
担心后训练微调搞不定，你要证明：**预测保留值不需要庞大的对齐训练，轻量级特征就够了。**
1. 提取第 $k$ 步生成时的 LLM **困惑度（Perplexity）、Token 概率分布的熵（Entropy），或者直接提取最后一层 hidden states**。
2. **不用深度学习，用机器学习**：训练一个简单的 XGBoost 或 Ridge Regression，输入上述特征，目标是回归预测刚刚算出来的 Oracle $r_k^*$。
3. 用这个 XGBoost 预测出的 $\hat{r}_k$ 替换掉上帝视角的 $r_k^*$，再跑一遍测试集模拟停止。
4. **👉 结论：如果这个简单的 ML 探针（Probe）依然能比“固定阈值停止”表现好，就证明了这个特征极易学习，根本不需要复杂的 PPO！**
