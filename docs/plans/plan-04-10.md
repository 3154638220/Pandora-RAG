### 二、高杠杆改进方向

#### 1. **F1 回归替代二分类**（已落地；实测：统一默认超参下未优于二分类）

当前 Probe 做的是二分类（Continue=1/Stop=0），但训练标签存在两个问题：

- **类别极度不均衡**：约 80% 标签为 Stop，Focal Loss 也未能有效解决
- **丢弃了连续信息**：Oracle margin 本身是连续值，二值化后信息大量损失（`margin_weight_floor=0.1` 只做了部分补偿）

**实现（仓库现状）：** `stage2/run_stage2.py` 默认 `--probe-target f1`：头输出经 `sigmoid` 压到 [0,1]，对 **Oracle 的 `expected_continue_val`**（`pretest/utils/weitzman.py` 中 V_{k+1}-c_{k+1}，与二分类 margin 同源的连续量）做 **margin 加权的 Huber（delta=0.1）**；Phase C 仍在 dev 上选阈值，推理规则仍为 `pred > threshold` 则继续。二分类路径保留：`--probe-target binary`。

```python
# 回归目标：expected_continue_val（clamp 到 [0,1]）；推理同原 Probe
pred = torch.sigmoid(logits)
loss = F.huber_loss(pred, target_expected_continue, delta=0.1)  # 再乘 margin 权重
```

**好处（动机仍成立）：**

- 回避 80% Stop 的类别不均衡
- 保留与 Oracle 决策相关的连续量，而非仅 0/1
- 输出在 [0,1] 上可视为可校准的质量代理，便于接 Stage3
- 实现成本低：loss + 标签构造 + CLI

**实测（与 §一「统一默认」对齐：`compress_dim=64`、`train_margin_min_abs=0`；`--artifact-suffix ablate_f1_regression`；2026-04-10）：**

| -------- | -------- | ---- | --------- | ------------ | ----- | ----------- | -------- | -------------------------------------------------------------- |
| HotpotQA | 0.4496   | 2.91 | 0.6232    | 72.1%        | 0.174 | **−0.065**  | 0.83     | `results/stage2_probe_table_hotpotqa_ablate_f1_regression.csv` |
| MuSiQue  | 0.1232   | 1.84 | 0.2526    | 48.8%        | 0.129 | **−0.056**  | 0.45     | `results/stage2_probe_table_musique_ablate_f1_regression.csv`  |
| 2Wiki    | 0.3131   | 3.24 | 0.5336    | 58.7%        | 0.220 | **−0.035**  | 0.81     | `results/stage2_probe_table_2wiki_ablate_f1_regression.csv`    |

#### 3. **序列级建模 / 多步信息聚合**（预计收益：中~高）

当前每一步被当作 **i.i.d. 样本**独立训练，完全丢失了轨迹内的**时序依赖**。Probe 在第 k 步做决策时看不到前几步自己给出的置信度和决策结果。

**具体建议 A（轻量）：** 加入 **历史聚合特征**——把前 k-1 步的 Probe 输出分数（或 shallow 特征的统计量）作为额外输入：

```python
# 新增特征维度
"probe_score_step_km1",      # 上一步 Probe 的 sigmoid 输出
"probe_score_running_mean",  # 前k-1步 Probe 分数均值
"max_f1_proxy_so_far",       # 历史最优质量代理值
```

**具体建议 B（更彻底）：** 用一个小型 **GRU/Transformer** 处理整条轨迹的步特征序列，直接在序列级别做"在第几步停止"的决策：

```python
class SequenceProbe(nn.Module):
    def __init__(self, step_dim, hidden_dim):
        self.step_encoder = nn.Linear(step_dim, hidden_dim)
        self.gru = nn.GRU(hidden_dim, hidden_dim, batch_first=True)
        self.head = nn.Linear(hidden_dim, 1)
    
    def forward(self, step_features_seq):  # [B, max_k, D]
        encoded = self.step_encoder(step_features_seq)
        outputs, _ = self.gru(encoded)
        return self.head(outputs)  # [B, max_k, 1] per-step continue prob
```

这能让模型学到如"前几步分数已经在下降 → 应该停止"这种时序模式。

**实现与复现（仓库现状）：** `stage2/run_stage2.py` 中 `--seq-history-features` 对应建议 A：在 **20 维浅层** 后拼接三维标量；训练阶段用 **Oracle** 的 `expected_continue_val`（f1 头）或 `action_label`（二分类头）作 teacher forcing 填「上一步值 / 历史均值 / 历史 max」；dev/test 与 Stage3 推理与 **自回归** 一致（用前序步 `sigmoid(logit)` 填这三维）。`--sequence-gru` 对应建议 B：`ProbeSequenceGRU`（与 `ProbeMLP_v2` 相同的步级编码 + `GRU` + 逐步 logits），`--gru-hidden-dim` 默认 128；与 A **互斥**。Checkpoint 写入 `seq_history_features` / `sequence_gru`，`--rethreshold-only` 与 Stage3 `stage2_probe` 适配器按字段选择批量或自回归/GRU 预计算概率。

### 三、中杠杆改进方向

#### 4. **Hidden State 提取策略改进**

当前只用 `last_token`，且从 4096→64 压缩过于激进。

- **Mean Pooling 混合**：`--hidden-state-key mean_pool`（代码已支持），或取 `0.5 * last_token + 0.5 * mean_pool`
- **多层特征**：从 LLM 的多个 transformer 层提取 hidden，用 learned attention 加权
- **Residual Compression**：在 hidden branch 中加入残差连接

```python
self.hidden_branch = nn.Sequential(
    nn.LayerNorm(hidden_state_dim),
    nn.Linear(hidden_state_dim, compress_dim),
    nn.GELU(),
    nn.Dropout(dropout),
)
# 改为：
self.proj = nn.Linear(hidden_state_dim, compress_dim)
self.residual = nn.Linear(compress_dim, compress_dim)
# forward: h = GELU(proj(x)) + residual(GELU(proj(x)))
```

**实测（与 §一「统一默认」对齐：`compress_dim=64`、`train_margin_min_abs=0`、F1 回归 Probe；2026-04-10）：**

**结论：** 在统一默认压缩维、**F1 回归** 与 Phase C 设定下，三种 Hidden 提取/分支改动 **均未超过 last_token 基线**；2Wiki 上 `last_mean_blend` 略优于 `mean_pool`，但仍低于基线。

#### 5. **多任务学习**（预计收益：中）

同时训练两个头：一个二分类头（Continue/Stop）+ 一个 F1 回归头，共享 backbone 特征：

```python
loss = α * bce_loss(continue_logit, action_label) + (1-α) * huber_loss(f1_pred, true_f1)
```

- 回归头给 backbone 提供更丰富的梯度信号
- 二分类头保持原有的阈值-停止机制不变
- 两者互相正则化

#### 6. **Phase C 阈值选择精细化**

当前 50 个候选阈值 + 4 个 λ 值，可能遗漏更优的工作点：

- 将候选阈值增加到 200 个（从 0.01~0.99，间隔 0.005）
- 按数据集特性调整 λ 范围（2Wiki 可能需要更激进的 λ）
- 考虑在 dev 上做 **bootstrapped threshold selection**，选择在多次 bootstrap 中表现最稳定的阈值

#### 7. **Ensemble / Test-Time 增强**

- 训练 3~5 个不同随机种子的 Probe，推理时取平均概率
- 或者同时训练一个 MLP Probe + 一个 XGBoost Probe，加权融合
- 成本低，通常能带来 0.005~0.015 的稳定提升

---

### 四、低杠杆 / 探索性方向

#### 8. **更好的质量代理特征**

`plan_claude.md` 已指出 `answer_logprob` 的细化方向：

- `answer_logprob_min` / `answer_logprob_std`：捕捉 token 级别的不确定性分布
- `delta_answer_logprob`：步间 logprob 变化趋势
- 修复 `llm_client` 中 `-1/0` 的 fallback 稀释问题

#### 9. **课程学习 (Curriculum Learning)**

先用高 margin（决策清晰的）样本训练，逐步加入低 margin（模糊的）样本：

```python
for epoch in range(epochs):
    margin_threshold = max(0.0, 0.2 - epoch * 0.01)  # 逐步降低
    # 只用 |margin| > margin_threshold 的样本
```

#### 10. **数据增强 / Mixup**

对特征向量做 mixup：随机插值两个样本的特征和标签。对于"模糊边界"（低 margin）样本尤其有帮助。

---

### 五、关键认知：信息论硬墙

所有已做实验一致指向一个核心事实：**Probe 的瓶颈在于无法观测真实 F1**。这意味着：

1. **不要期望追平 Original-GW**（它用真实 F1 做决策）——这在信息论上不可能
2. **最大收益来自"更好地利用已有信息"**（per-dataset 调参已验证有效；F1 回归在默认超参下未涨，见 §二.1；序列建模等仍值得试），而不是"找到新的魔法特征"
3. **论文叙事应将 Probe 与 Oracle 的差距转化为 E-value 存在的必要性论据**

### 六、推荐优先级排序


| 优先级    | 方向                          | 预计时间      | 预计增益           |
| ------ | --------------------------- | --------- | -------------- |
| **P0** | Per-dataset 最优配置组合          | 0 天（已有数据） | +0.01~0.03     |
| **P1** | F1 回归（已实现；默认下未涨）+ 组合调参/多任务  | 0.5~1 天   | 待验证（§二.1 基线为负） |
| **P1** | 序列级特征聚合（轻量版）                | 0.5~1 天   | +0.005~0.02    |
| **P1** | 多任务学习（分类+回归）                | 0.5 天     | +0.005~0.015   |
| **P2** | Ensemble（多种子平均）             | 0.5 天     | +0.005~0.015   |
| **P2** | Phase C 精细化                 | 0.5 天     | +0.002~0.008   |
| **P3** | Hidden state 提取改进           | 1~2 天     | 不确定            |
| **P3** | Curriculum learning / Mixup | 0.5 天     | +0.002~0.005   |


**P0 建议：** Per-dataset 最优配置组合仍是确定性收益。**F1 回归**已实现（`--probe-target f1`）；当前 Stage2 **默认**为 **binary** 头。在与 §一「统一默认」对齐的超参下，f1 头 **test Probe F1 三数据集均下降**（§二.1）；若论文或 Stage3 仍需要连续分数，可保留实现并转向「回归 + per-dataset 超参」或「分类+回归多任务」再评估。
