# Pandora-RAG Stage2 低成本最优停止计划：2026-04-19

> 状态：已基于当前 `cache/trajectories` 与 `artifacts/probe/*/probe_mlp_pdopt_best.pt` 完成追加分析。  
> 决策：**不重跑 Stage1，且 Stage2 主目标保持原设定**：`F1 - λ·cost`，并保留 `GW(dev)` 步数上界约束。  
> 定位：主线学习的是**低成本最优停止器**，不是“最高 F1 选择器”。

---

## 一、最终决策

- **主方法不改目标函数。**
  `stage2` 的训练标签、Phase C 阈值选择、Pandora / Weitzman 叙事都已经围绕 `F1 - λ·cost` 的最优停止展开；NeurIPS 主文应继续保持这一自洽设定。
- **纯 `max-F1` 阈值只作为补充分析。**
  现有 sweep 证明：同一 checkpoint 改成纯 F1 选阈值后，test F1 还能上升，但代价是平均检索步数明显增加。这说明当前策略仍有 quality headroom，但它更适合作为 appendix 的 `quality-first` operating point，而不是主结果。
- **Stop-RAG 的主对比口径改为预算匹配。**
  作为“低成本最优停止器”，Pandora 与 Stop-RAG 的公平比较不应是单点 raw `best-F1`，而应是：
  - 相同预算下谁的 F1 更高
  - 达到相同 F1 谁的预算更低
  - 两者在 `F1 vs avg_steps` Pareto 曲线上的相对位置

## 二、这轮分析真正说明了什么

### 2.1 Oracle 再次证明：更多步数不等于更高 F1

基于 `cache/trajectories/{dataset}/test/trajectories.jsonl` 的真实 F1 序列统计：

| 数据集 | 最优步落在 `step1-2` 的占比 | 从 `step2` 往后仍能继续提升的占比 | 轨迹中出现“后一步 F1 下降”的占比 |
| --- | --- | --- | --- |
| HotpotQA | `90.1%` | `12.5%` | `22.8%` |
| MuSiQue | `59.7%` | `42.9%` | `27.3%` |
| 2Wiki | `93.2%` | `9.5%` | `27.5%` |

更细的最优步分布：

| 数据集 | step1 | step2 | step3 | step4 | step5 |
| --- | --- | --- | --- | --- | --- |
| HotpotQA | `56.4%` | `33.7%` | `5.5%` | `2.9%` | `1.5%` |
| MuSiQue | `43.2%` | `16.5%` | `20.6%` | `11.8%` | `7.9%` |
| 2Wiki | `50.5%` | `42.7%` | `4.1%` | `2.0%` | `0.7%` |

结论不是“应该多走几步”，而是：

- HotpotQA 与 2Wiki 的收益主要集中在前两步
- MuSiQue 更拖尾，但后段同样会回落
- 因此合理目标应是**在收益-成本折中下停在合适步数**，而不是无条件追更高步数

### 2.2 纯 `max-F1` sweep 只是诊断，不应改成主设定

同一 `pdopt_best` checkpoint，仅改阈值，不改模型：

| 数据集 | 当前 `pdopt_best` | dev-max-F1 阈值后的 test | F1 变化 | 步数变化 |
| --- | --- | --- | --- | --- |
| HotpotQA | `0.6561 / 1.696` | `0.6969 / 2.683` | `+0.0408` | `+0.987` |
| MuSiQue | `0.4093 / 3.374` | `0.4195 / 3.712` | `+0.0102` | `+0.338` |
| 2Wiki | `0.5767 / 1.833` | `0.5942 / 2.205` | `+0.0176` | `+0.372` |

这说明：

- 当前 Phase C 的确在主动选择更省预算的工作点
- 纯 F1 阈值会把 Pandora 推向更“贪步数”的 operating point
- 这不是 bug，而是**主目标不同**

因此，这组数字的正确用途是：

- 证明模型本身还有质量 headroom
- 支持 appendix 中的 `best-F1 vs best-F1` 辅助分析
- 不用于替换主实验的 cost-aware 结果

### 2.3 当前训练标签与主叙事本来就是对齐的

`pretest/utils/weitzman.py::compute_trajectory_oracle` 生成的是 cost-aware DP Oracle 标签：

- `action_label = 1 if V_{k+1} - c_{k+1} > Q_k else 0`
- `expected_continue_val = V_{k+1} - c_{k+1}`

`stage2/run_stage2.py::_build_xyw` 里：

- `probe_target=binary` 学的是 `action_label`
- `probe_target=f1` 实际回归的也是 `expected_continue_val`

也就是说，当前 `stage2` 从监督到部署，学到的始终是：

> 什么时候继续检索的净收益更高

这正是低成本最优停止器应学的东西。

## 四、如何和 Stop-RAG 对比

### 4.1 先统一问题设定

公平对比必须满足：

- 同一批样本 id / 同一切分
- 同一最大检索轮数：`max_iterations=5`
- 同一 `repeat_size=1`
- 同一默认上下文长度：`2048`
- Stop-RAG 只能使用 `stop_rag_test.sh` 的**在线早停**结果

不允许拿 Stop-RAG 的：

- `dataset.sh` 生成的 full traces
- `stop_rag_find_best.sh` 的离线打分文件
- `compute_scores/*.jsonl` 的回放结果

去和 Pandora 的在线停止结果做最终 head-to-head。

### 4.2 预算怎么定义

当前最稳的统一口径是：

> `cost = c * t`

其中：

- `t` = 在线检索轮数
- Stop-RAG 用 `stop_iter`
- Pandora 用 `steps_used`

但论文主文建议直接报：

> `avg_steps`

原因是当两边使用同一个常数 `c` 时：

- `c * t` 与 `t` 完全等价
- `avg_steps` 更直观，也更不容易引发“这个 c 从哪来”的问题

在 Stop-RAG 尚未补齐对齐的 token / latency 统计之前：

- `avg_steps` 应作为主预算指标
- `token cost` / `latency` 只能作附加分析，不能作主对比口径

### 4.3 主表怎么比

作为低成本最优停止器，Pandora 与 Stop-RAG 的主表建议是：

1. `F1 @ matched avg_steps`
2. `EM @ matched avg_steps`
3. `avg_steps to reach the same F1`

也就是：

- 固定预算看谁质量更高
- 固定质量看谁更省预算

这比直接拿两个“各自最优单点 F1”互比更公平，也更贴合论文主 claim。

### 4.4 主图怎么画

主图建议统一为：

- 横轴：`avg_steps`
- 纵轴：`F1`
- 两边都 sweep threshold，画在线停止得到的 Pareto curve

然后报告：

- 哪一方在关键预算区间支配另一方
- Pandora 是否在低预算区间更优
- 或者 Pandora 是否能用更少步数到达 Stop-RAG 的同等 F1

### 4.5 Appendix 怎么补

因为 Stop-RAG 的默认阈值选择本身更偏 F1，所以 appendix 里可以再补一张：

- `best-F1 vs best-F1`

但这张表的作用是：

- 说明“如果都只追 F1，Pandora 还能到哪”

而不是承载主结论。

## 五、对论文叙事的直接影响

主文的核心 claim 应写成：

> **At the same retrieval budget, Pandora achieves higher answer quality; equivalently, to reach the same F1, Pandora uses fewer retrieval steps.**

而不是：

> Pandora 的单点 F1 比 Stop-RAG 更高

对应地：

- 主方法：保留 `F1 - λ·cost` + `GW(dev)` 步数上界
- Stop-RAG 主对比：`matched-budget / Pareto`
- `max-F1`：只放 appendix / ablation
